## Mínimos que os modelos reais exigem

1. Problema em comportamento **passado** (última vez), não hipotético.  
2. Persona / early adopter com contexto.  
3. Alternativas atuais + fricção.  
4. Intensidade (tempo/dinheiro/dor).  
5. O que **não** é o problema.  
6. Premissas marcadas como hipótese até validar.

## Nosso modelo-alvo (estrutura)

1. **Dicionário**  
2. Problem statement (quem + quando + dor + sucesso + fora)  
3. Persona primária  
4. Dor / evidência  
5. Fora de escopo  
6. Sucesso mensurável  
7. Entradas + canais do dia 1  
8. Regra “mesmo X” se aplicável  
9. Confirmado · Hipótese · Aberto  
10. Gate  

## Critérios de aceitação (esta fase)

| # | CA | Barra |
|---|-----|--------|
| D1 | Dicionário no topo | Obrigatório |
| D2 | Problem statement completo | Quem + dor + sucesso + não-é |
| D3 | Persona com **momento** | Não “todo mundo” |
| D4 | Sucesso mensurável | Número ou tempo |
| D5 | Matching / regra crítica fechada ou adiada com risco | Sem “abre no proto” |
| D6 | Entradas + canais dia 1 | Lista explícita |
| D7 | Gate gravado | fechado / adiado / bloqueado |
| D8 | Sem solução técnica densa no lugar do problema | Parking |
| **D.CL** | **CL0–CL5** — `shared/docs-clarity.md` | Posicionamento do leigo; teste do estranho; zero `qtd.`/meta de chat |

## Anti-padrões (Discovery)

| Anti-padrão | Sintoma |
|-------------|---------|
| Pitch na entrevista | Doc vende feature em vez de dor |
| Persona sentimento | “Pessoas cansadas de…” |
| Sucesso vago | “Achou” sem critério |
| Misturar jobs | “Qual modelo” + “qual anúncio” sem corte |
| Assumir sem o cliente | Preencheu lacuna sozinho |
| Meta de chat / abreviação | `qtd.`, “não inventar”, título de prompt |
