# Getting started

Primer is built by GitHub for GitHub. Primer provides common language to build cohesive, accessible, responsive experiences.

## A cohesive experience

GitHub has a global audience. Millions use GitHub every day for many different reasons, in many different ways. Familiar patterns help people navigate and discover features. If pages don’t share the same metaphors, people get confused.

Primer focuses on UX so people benefit from a platform that is cohesive no matter where they are. Familiar UI lets people focus on the task instead of parsing something that looks completely new.

## Inclusive and accessible design

Accessibility and inclusive design must be considered from the start — it deeply affects design, behavior, and how it’s built. Adding accessibility after the fact generally turns into a difficult retrofit.

## Design for efficiency

GitHub is a productivity platform. Aim for flow, focus, fast and compact experience. Primer patterns aim for accessible solutions that don’t dilute efficient interactions; responsive design that doesn’t reduce desktop into mobile-first only; calm and logical experiences.

## The Zen of GitHub (14 aphorisms)

> “Whether you call it taste, culture, or zen, there are underlying assumptions that members of an organization rely on to resolve ambiguity…” — Ben Balter

- Responsive is better than fast
- It’s not fully shipped until it’s fast
- Anything added dilutes everything else
- Practicality beats purity
- Approachable is better than simple
- Mind your words, they are important
- Speak like a human
- Half measures are as bad as nothing at all
- Encourage flow
- Non-blocking is better than blocking
- Favor focus over features
- Avoid administrative distraction
- Design for failure
- Keep it logically awesome
